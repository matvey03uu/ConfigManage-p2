# Конфигурационное управление (вариант 20)

Инструмент сбора данных и построения графа зависимостей пакетов.

## Этап 1. CLI-прототип

Реализован интерфейс командной строки. Программа принимает шесть параметров, проверяет их корректность и обрабатывает конфигурацию.

## Этап 2. Сбор данных

Реализовано получение информации о пакетах из репозитория Ubuntu.

Программа самостоятельно загружает индексы пакетов `Packages.gz`, распаковывает их и выполняет поиск пакета по имени и указанной версии.

После нахождения пакета программа извлекает поле `Depends` из его метаданных.

Для получения и обработки данных используются стандартные библиотеки Python. Готовые менеджеры пакетов и сторонние библиотеки для получения зависимостей не используются.

В качестве репозитория для проверки используется Ubuntu 24.04 LTS (Noble Numbat), архитектура `amd64`.

## Этап 3. Построение графа зависимостей

Реализовано построение графа зависимостей пакетов с учётом транзитивных зависимостей.

Для обхода графа используется алгоритм поиска в ширину (BFS) с рекурсивной обработкой очереди.

Программа:
- получает прямые зависимости корневого пакета;
- последовательно находит зависимости зависимых пакетов;
- учитывает заданную максимальную глубину обхода;
- предотвращает повторную обработку пакетов;
- корректно обрабатывает циклические зависимости;
- выводит построенный граф в терминал.

### Тестовый режим

Для проверки построения графа реализован тестовый режим.

Вместо URL репозитория указывается путь к текстовому файлу с описанием зависимостей. Имена пакетов в тестовом файле должны состоять из заглавных латинских букв.

Формат файла:

```text
A: B, C
B: D
C: D
D:
```

Каждая строка содержит имя пакета, двоеточие и список его прямых зависимостей. Если зависимостей нет, после двоеточия оставляется пустое значение.

В тестовом режиме проверяется корректность имён пакетов, отсутствие повторных описаний и наличие всех указанных зависимостей.

### Ограничение глубины

Корневой пакет имеет глубину `0`.

Например, для графа `A -> B, C`, `B -> D`, `C -> D`:

- глубина `0` — только пакет `A`;
- глубина `1` — пакеты `A`, `B`, `C`;
- глубина `2` — пакеты `A`, `B`, `C`, `D`.

### Особенности получения транзитивных зависимостей

Для корневого пакета используется указанная версия. Для транзитивных пакетов выполняется поиск по имени без ограничения версии: используется первый найденный вариант в индексах выбранного репозитория.

Альтернативы зависимостей, разделённые символом `|`, рассматриваются как отдельные возможные зависимости.

## Параметры командной строки

| Параметр | Назначение | Проверка |
|---|---|---|
| `--package` | Имя анализируемого пакета | Не пустое |
| `--repository` | URL репозитория или путь к тестовому файлу | Проверяется с учётом режима |
| `--test-mode` | `true` для тестового файла, `false` для URL | Только `true` или `false` |
| `--version` | Версия корневого пакета | Проверяется формат версии Ubuntu/Debian |
| `--output` | Имя выходного файла | Только имя файла с расширением `.svg` |
| `--max-depth` | Максимальная глубина анализа | Целое число не меньше нуля |

## Структура проекта

- `src/main.py` — запуск программы, построение графа и вывод результатов.
- `src/config.py` — обработка и проверка параметров командной строки.
- `src/repository.py` — загрузка индексов Ubuntu и поиск пакетов.
- `src/package_parser.py` — разбор метаданных и извлечение зависимостей.
- `src/dependency_graph.py` — построение графа алгоритмом BFS с рекурсией.
- `src/repository_file.py` — загрузка и проверка тестового описания графа.
- `tests/test_config.py` — тестирование параметров командной строки.
- `tests/test_repository.py` — тестирование получения и поиска пакетов.
- `tests/test_package_parser.py` — тестирование разбора зависимостей.
- `tests/test_dependency_graph.py` — тестирование построения графа.
- `tests/test_repository_file.py` — тестирование загрузки тестового графа.
- `tests/test_main.py` — тестирование интеграции программы.
- `tests/repository.txt` — тестовый файл с описанием зависимостей.

## Запуск в Windows

Из корневой директории проекта выполните команду для работы с настоящим репозиторием:

```bat
python src/main.py --package curl --repository https://archive.ubuntu.com/ubuntu --test-mode false --version 8.5.0-2ubuntu10 --output dependencies.svg --max-depth 2
```

Для запуска в тестовом режиме:

```bat
python src/main.py --package A --repository tests/repository.txt --test-mode true --version 1.0 --output dependencies.svg --max-depth 2
```

## Пример результата

Для тестового графа при глубине `2` программа выводит:

```text
Пакет: A
Версия: 1.0
Максимальная глубина: 2
Граф зависимостей:
A -> B, C
B -> D
C -> D
D -> нет зависимостей
```

## Тестирование

Для проверки корректности работы программы используются автоматические тесты на основе стандартной библиотеки Python `unittest`.

### Запуск тестов

Из корневой директории проекта выполните:

```bat
python -m unittest discover -s tests -v
```

### Проверяемые случаи

В ходе тестирования проверяются:

- корректная обработка параметров командной строки;
- проверка URL репозитория и существования тестового файла;
- обработка некорректных значений максимальной глубины;
- поиск пакета по имени и версии;
- извлечение прямых и альтернативных зависимостей;
- построение графа зависимостей;
- соблюдение ограничения максимальной глубины;
- обработка циклических зависимостей;
- обработка пакетов без зависимостей;
- проверка формата тестового файла;
- обработка неизвестных и повторно описанных пакетов;
- интеграция тестового и обычного режимов.

### Результат тестирования

На третьем этапе успешно пройдены 30 автоматических тестов:

```text
Ran 30 tests
OK
```

Сообщение `OK` означает, что все автоматические тесты завершились успешно.

Если тест обнаруживает ошибку, `unittest` выводит информацию о неудачном тесте и причину сбоя.
