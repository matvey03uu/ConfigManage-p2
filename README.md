# Конфигурационное управление (вариант 20)

Инструмент сбора и визуализации графа зависимостей пакетов.

## Этап 1. CLI-прототип

На первом этапе реализован интерфейс командной строки. Программа принимает шесть параметров, проверяет их корректность и выводит в формате `ключ: значение`.

## Этап 2. Сбор данных

На втором этапе реализовано получение информации о пакетах из репозитория Ubuntu.

Программа самостоятельно загружает индексы пакетов `Packages.gz`, распаковывает их и выполняет поиск пакета по имени и указанной версии.

После нахождения пакета программа извлекает поле `Depends` из его метаданных и выводит список прямых зависимостей в терминал.

Для получения и обработки данных используются стандартные библиотеки Python. Готовые менеджеры пакетов и сторонние библиотеки для получения зависимостей не используются.

В качестве репозитория для проверки используется Ubuntu 24.04 LTS (Noble Numbat), архитектура `amd64`.

На данном этапе программа получает только прямые зависимости. Поиск транзитивных зависимостей и построение графа будут реализованы на следующих этапах.

## Параметры командной строки

| Параметр | Назначение | Проверка |
|---|---|---|
| `--package` | Имя анализируемого пакета | Не пустое |
| `--repository` | URL репозитория или путь к тестовому файлу | Проверяется с учётом режима |
| `--test-mode` | `true` для тестового файла, `false` для URL | Только `true` или `false` |
| `--version` | Версия пакета | Проверяется формат версии Ubuntu/Debian |
| `--output` | Имя выходного файла | Только имя файла с расширением `.svg` |
| `--max-depth` | Максимальная глубина анализа | Целое число не меньше нуля |

## Структура проекта

- `src/main.py` — запуск программы и вывод результатов.
- `src/config.py` — обработка и проверка параметров командной строки.
- `src/repository.py` — получение и обработка данных репозитория.
- `src/package_parser.py` — разбор метаданных пакетов и извлечение зависимостей.
- `tests/test_config.py` — тестирование параметров командной строки.
- `tests/test_repository.py` — тестирование получения и поиска пакетов.
- `tests/test_package_parser.py` — тестирование разбора зависимостей.
- `tests/repository.txt` — тестовый файл репозитория.

## Запуск в Windows

Из корневой директории проекта выполните команду:

```bat
python src/main.py --package curl --repository https://archive.ubuntu.com/ubuntu --test-mode false --version 8.5.0-2ubuntu10 --output dependencies.svg --max-depth 2
```

В качестве версии указана `8.5.0-2ubuntu10`. Она должна присутствовать в индексах выбранного репозитория.

## Пример результата

При успешном выполнении программа выводит информацию о найденном пакете и его прямых зависимостях:

```text
Пакет: curl
Версия: 8.5.0-2ubuntu10
Прямые зависимости:
  1. libc6 (>= 2.34)
  2. libcurl4t64 (= 8.5.0-2ubuntu10)
  3. zlib1g (>= 1:1.1.4)
```

Поле `Depends` содержит имена зависимых пакетов и условия, которым должны соответствовать их версии.

## Тестирование

Для проверки корректности работы программы используются автоматические тесты на основе стандартной библиотеки Python `unittest`.

Тесты находятся в директории `tests/`.

### Запуск тестов

Из корневой директории проекта выполните команду:

```bat
python -m unittest discover -s tests -v
```

### Проверяемые случаи

В ходе тестирования проверяются:

- корректная обработка параметров командной строки;
- проверка URL репозитория;
- проверка существования тестового файла репозитория;
- обработка некорректных значений максимальной глубины;
- проверка формата версии пакета;
- проверка имени выходного файла и его расширения;
- поиск пакета по имени и версии;
- обработка ситуации, когда пакет или его версия не найдены;
- извлечение прямых зависимостей из метаданных;
- обработка альтернативных зависимостей и ограничений версий.

### Результат тестирования

Если все тесты пройдены успешно, в терминале отображается сообщение:

```text
Ran 15 tests
OK
```

Вместо `N` будет указано фактическое количество выполненных тестов.

Сообщение `OK` означает, что все автоматические тесты завершились успешно.

Если тест обнаруживает ошибку, `unittest` выводит информацию о неудачном тесте и причину сбоя.
